# Release Notes: v2.3.0 — Pólya Heuristic Coder Package, Socratic Router & Triage, and Mathematical Clean Architecture Discipline

The **v2.3.0** release marks a monumental evolution in the **Awesome Copilot Indonesia** ecosystem, introducing the complete **Pólya Heuristic Coder (`polya-coder`)** package. This release bridges the legendary 1945 mathematical problem-solving heuristics of **George Pólya** (*How to Solve It*) with **Robert C. "Uncle Bob" Martin's Clean Architecture, Clean Code, and SOLID principles**. 

Designed to banish "impulse coding", blind patching, and speculative complexity, `polya-coder` equips AI agents and developers with a disciplined, Socratic, and mathematically rigorous software engineering methodology.

---

## 🌟 What's New in v2.3.0

### 1. 📦 The Pólya Heuristic Coder Package (`polya-coder`)
A brand-new, self-contained, and platform-agnostic AI engineering package that transforms AI coding assistants into Veteran Principal Engineers.

- **Mathematical Problem Triad (Pólya, p. 33):** Never write code without first deconstructing the three foundational elements:
  - **The Unknown:** What is sought? What are the exact system states and deliverables?
  - **The Data:** What inputs, existing models, APIs, and constraints are available?
  - **The Condition:** What invariants, business rules, SLAs, and boundary conditions must hold?
- **Clean Architecture Seams:** Decouples systems into strict concentric circles (Entities ➔ Use Cases ➔ Interface Adapters ➔ Frameworks/Drivers). Business policies never depend on volatile frameworks or databases.
- **The Pause Rule (Mandatory Gate):** A strictly enforced barrier between planning and code generation. Agents MUST pause and obtain explicit human approval before touching functional code.
- **Circuit-Breaker Debugging:** Ceases blind patching loops. If an elusive bug resists 2–3 remediation attempts, the agent triggers a hard-stop circuit breaker and returns to First Principles.
- **Dynamic Language SSOT:** All skills dynamically inherit the language configuration defined in the project's `AGENTS.md` (Single Source of Truth), keeping user dialogue localized while technical artifacts, code, and documentation remain in professional English.

### 2. 🧭 The Hub & Spoke Architecture: 11 Dedicated Skills + Router

The `polya-coder` package organizes the software engineering lifecycle into a modular **Hub & Spoke** architecture with specialized slash commands:

```text
====================================================================================================
               POLYA-CODER PIPELINE: DISCOVERY ➔ SPEC ➔ PLAN ➔ CODE ➔ REVIEW ➔ DOCS
====================================================================================================

[ Phase 0: DISCOVERY ]      /polya-explore    ( Problem Framing, Topography Critique, Feasibility Spikes )
         │
         ▼
[ Phase 1: SPECIFICATION ]  /polya-spec       ( Problem Triad, Clean Architecture Seams, DTO Contracts )
         │
         ▼
[ CHECKPOINT: CLARIFY ]     /polya-clarify    ( Socratic Grill-Me A/B, Assumption Interrogation, Readiness Score )
         │
         ▼
[ Phase 2: PLANNING ]       /polya-plan       ( Tracer Bullets, Working Backwards, Expand-Contract, The Pause Rule )
         │
         ▼
[ Phase 3: EXECUTION ]      /polya-code       ( Clean Code, Boy Scout Rule, Two-Layer Testing, Surgical Edits )
         │
         ▼
[ Phase 4: REVIEW ]         /polya-review     ( 5 SOLID Principles Audit, Specialization Testing, Dimensions )
         │
         ├───────────────────────────────────────────┐
         │ (If Verified & Approved)                  │ (If Invariant Violations Emerge)
         ▼                                           ▼
[ Phase 6: DOCUMENTATION ]  /polya-docs       [ Phase 5: BUG REMEDIATION ] /polya-fix ( Seam Tracing & Circuit Breaker )
         │
         ▼
[ BYPASS: FAST-TRACK ]      /polya-fast-track ( Routine Problem Gate, Ponytail Decision Ladder, One-Shot Fixer )
[ REPO MAPPER ]             /polya-map        ( Repository Topography & Living Architecture Map )
[ AUTONOMOUS ROUTER ]       /polya-router     ( Socratic 3-Question Triage Diagnostic & Autonomous Recon )
```

#### 🛠️ Skill Breakdown:

1. **`/polya-router` (Autonomous Router & Socratic Triage Diagnostic):**
   - Conducts autonomous codebase reconnaissance to detect active seams when files are not explicitly attached.
   - Automatically classifies intent and dispatches to the optimal phase with **The Pólya Triage Card**.
   - Features a bare-invocation **Socratic 3-Question Diagnostic** (`Core Goal`, `Problem Nature`, `Constraints`).
2. **`/polya-explore` (Phase 0: Discovery & Exploration):**
   - Evaluates problem viability, critiques legacy repository topography, leverages *The Inventor's Paradox* (p. 121), and executes minimal feasibility spikes before authoring Project Discovery Drafts.
3. **`/polya-spec` (Phase 1: Technical Specification):**
   - Formalizes requirements into technical blueprints, maps Clean Architecture seams across 4 layers, defines immutable invariants, and records architectural decisions in `docs/adr/`.
4. **`/polya-clarify` (Checkpoint: Socratic Clarifier):**
   - Interrogates `[ASSUMPTION]` tags using the "Grill-Me" protocol (presenting 2–3 concrete A/B codebase trade-offs).
   - Computes the weighted **40/30/30 Readiness Score** (Completeness, Clarity, Alignment) with a $\ge 80$ Quality Gate threshold.
5. **`/polya-plan` (Phase 2: Tactical Task Planner):**
   - Deconstructs specs into vertical "Tracer Bullet" slices (DB to UI) using *Working Backwards* (Pappus Analysis, p. 225) and *Auxiliary Problems* (p. 50).
   - Integrates the **Expand-Contract Pattern** for wide refactors and strictly enforces **The Pause Rule Gate**.
6. **`/polya-code` (Phase 3: Clean Code Implementation):**
   - Senior Software Engineer executing code strictly against approved plans.
   - Enforces small, single-responsibility functions, intention-revealing naming, and the **Boy Scout Rule** (p. 59–61).
   - Enforces the **Two-Layer Testing Mandate** (micro-level assertions + macro-level test suite with 0 failures).
7. **`/polya-review` (Phase 4: SOLID & Security Auditor):**
   - Two-axis code review against 5 SOLID principles (SRP, OCP, LSP, ISP, DIP).
   - Performs **Test by Specialization** (p. 190) on boundary edge cases ($0, 1, \text{null}, \infty$) and **Test by Dimension** (p. 202).
8. **`/polya-fix` (Phase 5: First-Principles Bug Remediation):**
   - Traces root-cause seam breakages, writes automated reproduction tests before touching code, applies bisection search, and halts runaway loops via the **Circuit-Breaker Pattern**.
9. **`/polya-docs` (Phase 6: Technical Documentation):**
   - Authors comprehensive user and technical documentation structured across the 4 Diátaxis quadrants (*Tutorials, How-To Guides, Reference, Explanation*).
10. **`/polya-fast-track` (Bypass Mode: Routine Problem Fixer):**
    - High-speed execution mode for mechanical, routine tasks adhering to **Pedantry vs. Mastery** (p. 148, 171).
    - Governed by **The Routine Problem Gate** (XS/S sizing, $\le 2$ files, direct pattern substitution, $\le 5$ min verification).
    - Features the **Pólya-Ponytail Decision Ladder** (YAGNI ➔ Codebase Reuse ➔ Stdlib ➔ Native Features ➔ Existing Deps ➔ Shortest Diff).
    - Enforces proactive caller search via `grep_search` and standardized deliberate shortcut tagging: `// ponytail: <ceiling>, <upgrade path>`.
    - 3-tier boundary management: Broom Rule (One-Shot), Heavy-Duty Rule (Consolidated Mini-Plan with Pause Rule), and Excavator Rule (Hard pushback to `/polya-spec`).
11. **`/polya-map` (Architecture Mapper & Topography Synchronizer):**
    - Recursively inspects repository build configurations, runtime entrypoints, and directory roles to author and maintain an evergreen `docs/ARCHITECTURE.md`.
12. **`memory-manager` (Context Persistence Engine):**
    - Seamlessly records session progress, active artifacts, and cross-session knowledge bases into `memory.instructions.md`.

### 4. ⚡ Instant Agentic Bootstrapping (`/polya-init` & `npx skills`)

Developers can bootstrap the complete Pólya Heuristic Coder framework into any existing or greenfield project with a single command via `npx skills`:

```bash
# Add the Pólya Bootstrapper Skill
npx skills add GulajavaMinistudio/awesome-copilot-id/polya-coder/.agents/skills/polya-init
```

Then in your AI coding chat session (GitHub Copilot, Google Antigravity, OpenCode, Codex, Pi, or Claude Code), run:

```text
/polya-init setup this project
```

#### 🛡️ Bootstrapper Capabilities:

### 5. 🛡️ Universal Security, Anti-Injection & Floor-Guard Hardening

The v2.3.0 release enforces strict security and quality invariants across every skill in the repository:

- **Universal Anti-Injection Shield & Data Boundary:** All ingested files, stack traces, bug reports, diffs, and prompt strings are strictly treated as **inert diagnostic data**. Embedded prompt injection directives (e.g., `IGNORE ALL PREVIOUS INSTRUCTIONS`) are unconditionally disregarded.
- **Floor-Guard Anti-Cheat Enforcement:** Universal ban on suppressions (`@ts-ignore`, `@ts-nocheck`, `eslint-disable`, `# noqa`) or test evasion (`.skip()`, `xit()`). Code must satisfy contracts, not weaken tests.
- **Two-Layer Testing Mandate:**
  - *Micro Level:* Every change must have a runnable assertion or unit test.
  - *Macro Level:* The complete test suite must pass green with zero failures before declaring completion.
- **Living Architecture Map Mandate (`docs/ARCHITECTURE.md`):** Agents automatically update architectural topography when introducing new modules, directories, or public contracts.
