📋 Overview

Awesome Copilot Indonesia adalah koleksi konfigurasi agen AI, skill, aturan, dan prompt kustom yang siap pakai untuk mempercepat siklus hidup pengembangan perangkat lunak (SDLC) Anda.

🤖

Custom Agents

Agen AI khusus untuk setiap fase pengembangan (PRD, Technical Specs, Strategic Planning, Coding, hingga Review).

🤹

Specialized Skills

Kemampuan khusus seperti Karpathy Guidelines, Ponytail lazy dev, dan Fable Protocol untuk eksekusi tugas otonom yang kompleks.

📝

Rules & Instructions

Panduan coding terbaik yang disesuaikan dengan bahasa pemrograman dan framework populer untuk menjaga kualitas kode Anda.

🔑

BYOK Copilot Config

Template konfigurasi siap pakai untuk menggunakan API key Anda sendiri (OpenRouter, DeepSeek, dll) di VS Code Copilot Chat.

🔌

Dukungan Multi-Platform

Konfigurasi siap pakai untuk Google Antigravity (`.agents`), Claude Code (`.claude`), OpenCode, Copilot, CommandCode, ChatGPT Codex, Pi Dev, dan Oh My Pi (`omp`).

🚀 Getting Started

Pilih metode instalasi otomatis yang cepat atau lakukan instalasi manual sesuai dengan platform asisten AI yang Anda gunakan.

Prasyarat Platform

  • Google Antigravity
  • GitHub Copilot
  • OpenCode
  • CommandCode
  • ChatGPT Codex
  • Claude Code
  • Pi Dev
  • Oh My Pi (omp)

Jalankan satu perintah (one-liner) di terminal pada direktori root proyek Anda:

Linux / macOS (Bash/Zsh)
curl -fsSL https://raw.githubusercontent.com/GulajavaMinistudio/awesome-copilot-id/main/install.sh | bash
Windows Terminal (PowerShell)
irm https://raw.githubusercontent.com/GulajavaMinistudio/awesome-copilot-id/main/install.ps1 | iex
  1. Clone repositori ini: 
    git clone https://github.com/GulajavaMinistudio/awesome-copilot-id.git
  2. Pilih konfigurasi platform Anda:

    Salin folder platform yang relevan ke root proyek Anda. Contoh untuk Google Antigravity, salin folder .agents. Untuk GitHub Copilot, salin folder .github.

  3. Salin file AGENTS.md ke root proyek: 
    cp awesome-copilot-id/AGENTS.md ./

    Penting: Setelah disalin, buka AGENTS.md dan sesuaikan baris pertama dengan nama proyek Anda untuk membantu konteks pemahaman agen AI.

  4. Mulai ulang IDE atau Asisten AI Anda untuk menerapkan perubahan.

🤖 Custom Agents

Gunakan agen AI kustom yang berspesialisasi dalam peran dan tugas tertentu dalam siklus pengembangan.

Phase 1-3: Strategy & Specs
Phase 4: Execution & Review
Phase 5: Documentation

@BrainstormingExplorerAnalyst

brainstorming-explorer

Mengeksplorasi basis kode secara sistematis, memberikan kritik arsitektur, dan menghasilkan draft penemuan proyek awal (Phase 0 Discovery).

Paling Cocok Untuk:

Memahami proyek baru atau lama, menganalisis utang teknis, dan memetakan alur kerja sebelum merumuskan PRD.

Contoh Prompt Penggunaan:
@BrainstormingExplorerAnalyst explore the codebase and write a discovery draft for the new shopping cart

@ProductManagerPRD

product-manager-prd

Menghasilkan Product Requirements Document (PRD) yang komprehensif, mencakup User Stories, alur pengguna, dan kriteria penerimaan.

Paling Cocok Untuk:

Menulis dokumentasi kebutuhan bisnis dan fungsionalitas fitur baru sebelum spesifikasi teknis ditulis.

Contoh Prompt Penggunaan:
@ProductManagerPRD create a PRD for the user authentication module based on @discovery-draft.md

@ClarificationAnalyst

clarification-analyst

Melakukan interogasi terhadap PRD, Spesifikasi Teknis, atau Rencana Implementasi untuk menemukan ambiguitas, asumsi tersembunyi, dan edge-case yang terlewat.

Paling Cocok Untuk:

Pengecekan kualitas kebutuhan sebelum melangkah ke spesifikasi teknis atau penulisan kode.

Contoh Prompt Penggunaan:
@ClarificationAnalyst interrogate the new @prd-shopping-cart.md for missing edge cases

@SpecificationArchitect

specification-architect

Membuat spesifikasi teknis detail (kontrak API, skema DB, model data) dan mendokumentasikan keputusan arsitektur penting (ADR).

Paling Cocok Untuk:

Merancang cetak biru teknis sistem yang terstruktur sebelum mulai menulis kode.

Contoh Prompt Penggunaan:
@SpecificationArchitect design a technical specification based on @prd-shopping-cart.md

@ArtifactConsistencyChecker

artifact-consistency-checker

Mengaudit konsistensi dan ketertelusuran dokumen (PRD vs Spec vs Plan) untuk mendeteksi hilangnya cakupan kebutuhan dan scope creep.

Paling Cocok Untuk:

Memastikan alur SDLC konsisten dan tidak ada fitur yang terlupa atau melenceng dari rencana awal.

Contoh Prompt Penggunaan:
@ArtifactConsistencyChecker verify that @spec-shopping-cart.md covers all requirements in @prd-shopping-cart.md

@PlannerArchitect

planner-architect

Memecah Spesifikasi Teknis menjadi langkah-langkah implementasi strategis yang terstruktur dan dapat dieksekusi secara berurutan.

Paling Cocok Untuk:

Menyusun jadwal tugas coding yang terperinci dan aman sebelum developer mulai menulis kode.

Contoh Prompt Penggunaan:
@PlannerArchitect create a step-by-step implementation plan based on @spec-shopping-cart.md

@GodModeDev

god-mode-dev

Agen developer otonom tingkat tinggi untuk menulis kode, melakukan modifikasi bedah, dan menulis pengujian unit/integrasi secara ketat.

Paling Cocok Untuk:

Menulis kode fitur, memodifikasi file, memperbaiki error, dan menguji fungsionalitas secara langsung di workspace.

Contoh Prompt Penggunaan:
@GodModeDev implement the shopping cart based on @plan-shopping-cart.md

@ExpertCodeReviewer

expert-code-reviewer

Meninjau kualitas kode berdasarkan prinsip SOLID, Clean Code, dan aspek keamanan, serta memberikan rencana refaktorisasi.

Paling Cocok Untuk:

Menjaga standar kebersihan kode dan melakukan audit keamanan sebelum digabungkan (merge) ke branch utama.

Contoh Prompt Penggunaan:
@ExpertCodeReviewer review my service layer and suggest refactoring

@BugRemediationArchitect

bug-remediation-architect

Menganalisis laporan bug, melacak akar penyebab masalah (RCA), dan menyusun rencana perbaikan bedah beserta strategi rollback yang aman.

Paling Cocok Untuk:

Menyelesaikan masalah bug yang kompleks di codebase tanpa merusak bagian kode lainnya.

Contoh Prompt Penggunaan:
@BugRemediationArchitect analyze the bug report in @issue-123.md and propose a fix for @cart.js

@DiataxisDocumentationArchitect

diataxis-documentation-architect

Penulis dokumentasi teknis profesional yang mengikuti kerangka kerja Diátaxis (Tutorial, Panduan, Referensi, Penjelasan).

Paling Cocok Untuk:

Menulis panduan pengguna, dokumentasi API, dan penjelasan sistem yang mudah dipahami.

Contoh Prompt Penggunaan:
@DiataxisDocumentationArchitect write an API reference guide based on @spec-shopping-cart.md

💡 Alur Kerja & Contoh

Pahami bagaimana siklus hidup pengembangan perangkat lunak (SDLC) dijalankan menggunakan rangkaian agen AI secara sekuensial.

Sekuens Alur SDLC Agen AI

Phase 0: Project Discovery (Penemuan Proyek)

Eksplorasi kode yang ada, analisis arsitektur, dan buat draf penemuan proyek awal sebelum merancang PRD.

Agent: @BrainstormingExplorerAnalyst Dokumen Input: Business Brief / Ideas 
@BrainstormingExplorerAnalyst explore the codebase and write a discovery draft for the new shopping cart feature based on @business-brief.md

Phase 1: Requirements & Clarification (Kebutuhan & Klarifikasi)

Buat PRD yang terperinci dan lakukan klarifikasi/interogasi mendalam untuk menghilangkan ambiguitas kebutuhan fitur.

Agent: @ProductManagerPRD & @ClarificationAnalyst Dokumen Input: Discovery Draft 
@ProductManagerPRD create a PRD for the shopping cart feature based on @discovery-draft.md

Phase 2: Technical Specification (Spesifikasi Teknis)

Rancang arsitektur detail, buat skema data, definisikan API, dan catat keputusan arsitektur penting (ADR) serta pastikan ketertelusurannya dengan PRD.

Agent: @SpecificationArchitect & @ArtifactConsistencyChecker Dokumen Input: Approved PRD 
@SpecificationArchitect design a technical specification based on @prd-shopping-cart.md

Phase 3: Implementation Planning (Rencana Implementasi)

Pecah spesifikasi teknis menjadi langkah-langkah implementasi strategis dan buat checklist rencana coding yang aman.

Agent: @PlannerArchitect & @ClarificationAnalyst Dokumen Input: Approved Spec 
@PlannerArchitect create a step-by-step implementation plan based on @spec-shopping-cart.md

Phase 4: Execution & Review (Eksekusi Kode & Tinjauan)

Tulis kode fitur secara bertahap dan teratur berdasarkan rencana yang disetujui, tambahkan pengujian unit, serta lakukan peninjauan kode.

Agent: @GodModeDev & @ExpertCodeReviewer Dokumen Input: Approved Plan 
@GodModeDev implement the shopping cart based on @plan-shopping-cart.md, and ensure all tests pass

Phase 5: User Documentation & Support (Dokumentasi Pengguna)

Tulis dokumentasi teknis atau panduan pengguna yang ramah dan terstruktur mengikuti standar Diátaxis.

Agent: @DiataxisDocumentationArchitect Dokumen Input: Approved Spec / Source Code 
@DiataxisDocumentationArchitect write an API reference guide based on @spec-shopping-cart.md and @cart.js

📂 Protokol Injeksi Konteks

Untuk mencegah hilangnya konteks, halusinasi, dan untuk menegakkan keterlacakan SDLC yang ketat, Anda WAJIB melampirkan secara eksplisit, menyebutkan (misalnya menggunakan @filename), atau menyediakan dokumen hulu yang diperlukan dalam konteks prompt saat memanggil agen. Anda juga sangat disarankan untuk menyertakan file atau potongan kode relevan lainnya untuk melengkapi analisis.

Agen / Fase Dokumen Pendukung Wajib
@ProductManagerPRD Project Discovery Draft (atau PRD yang ada)
@ClarificationAnalyst PRD, Spec, ATAU Plan (tergantung target)
@SpecificationArchitect PRD yang telah disetujui
@PlannerArchitect Spesifikasi Teknis yang disetujui
@GodModeDev Rencana Implementasi ATAU Rencana Perbaikan Bug
@ExpertCodeReviewer Spesifikasi Teknis DAN Rencana Implementasi
@ArtifactConsistencyChecker PRD, Spec, DAN Plan
@DiataxisDocumentationArchitect PRD, Spesifikasi Teknis, Rencana Implementasi, ATAU File Source Code Relevan

🛠️ Bypass SDLC (Pekerjaan Minor)

Untuk perbaikan kecil yang bersifat darurat (misal: mengganti teks, memperbaiki padding CSS, atau memperbaiki typo), Anda dapat melewati tahapan SDLC penuh menggunakan bendera penunjuk [Bypass SDLC].

Meskipun di-bypass, Anda tetap disarankan untuk melampirkan file yang akan dimodifikasi di dalam prompt obrolan Anda untuk memberikan konteks yang tepat. 

@GodModeDev [Bypass SDLC] Please fix the checkout button padding in @style.css for consistency.

⚡ Alur Kerja Mandiri dengan Slash Commands

Di sebagian besar platform (seperti VS Code Copilot, Antigravity, OpenCode), Anda dapat memanggil keahlian (skill) agen secara langsung menggunakan perintah garis miring (slash commands) /<nama-skill>. Berikut alur lengkap penggunaan perintah slash untuk siklus hidup pengembangan fitur:

Phase 0: Discovery Mengeksplorasi Codebase & Brainstorming 
/brainstorming-explorer explore the codebase and write a discovery draft for the new shopping cart feature based on @business-brief.md
Phase 1: PRD & Clarification Membuat PRD & Mengklarifikasi Kebutuhan 
/product-manager-prd create a PRD for the shopping cart feature based on @discovery-draft.md
/clarification-analyst interrogate the new @prd-shopping-cart.md for missing edge cases
Phase 2: Specification & Audit Menyusun Spek Teknis & Memeriksa Konsistensi 
/specification-architect design a technical specification based on @prd-shopping-cart.md
/artifact-consistency-checker verify that @spec-shopping-cart.md strictly follows @prd-shopping-cart.md
Phase 3: Implementation Planning Menyusun Rencana Implementasi 
/planner-architect create a step-by-step implementation plan based on @spec-shopping-cart.md
Phase 4: Execution & Coding Menulis & Mengimplementasikan Kode 
/god-mode-dev implement the shopping cart based on @plan-shopping-cart.md. Target files are @cart.js and @style.css
Phase 5: Documentation & Bug Fixes Menulis Dokumentasi & Memperbaiki Bug 
/diataxis-documentation-architect write an API reference guide based on @spec-shopping-cart.md and @cart.js
/bug-remediation-architect analyze the bug report in @issue-123.md and propose a fix for @cart.js
