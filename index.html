📋 Overview

Awesome Copilot Indonesia adalah koleksi konfigurasi agen AI, skill, aturan, dan prompt kustom yang siap pakai untuk mempercepat siklus hidup pengembangan perangkat lunak (SDLC) Anda.

🤖

Custom Agents

Agen AI khusus untuk setiap fase pengembangan (PRD, Technical Specs, Strategic Planning, Coding, hingga Review).

🤹

Specialized Skills

Kemampuan khusus seperti Project Researcher untuk pemetaan arsitektur otomatis, Karpathy Guidelines, Ponytail lazy dev, TDD Implement, dan Fable Protocol untuk eksekusi tugas otonom yang kompleks.

📝

Rules & Instructions

Panduan coding terbaik yang disesuaikan dengan bahasa pemrograman dan framework populer untuk menjaga kualitas kode Anda.

🔑

BYOK Copilot Config

Template konfigurasi siap pakai untuk menggunakan API key Anda sendiri (OpenRouter, DeepSeek, dll) di VS Code Copilot Chat.

🔌

Dukungan Multi-Platform

Konfigurasi siap pakai untuk Google Antigravity (`.agents`), Claude Code (`.claude`), OpenCode, Copilot, CommandCode, ChatGPT Codex, Pi Dev, dan Oh My Pi (`omp`).

Jalankan satu perintah (one-liner) di terminal pada direktori root proyek Anda:

Linux / macOS (Bash/Zsh)
curl -fsSL https://raw.githubusercontent.com/GulajavaMinistudio/awesome-copilot-id/main/install.sh | bash
Windows Terminal (PowerShell)
irm https://raw.githubusercontent.com/GulajavaMinistudio/awesome-copilot-id/main/install.ps1 | iex
Penting: Setelah instalasi selesai, buka file AGENTS.md di root proyek Anda dan ubah:
1. Placeholder [Your Application Name] dengan nama proyek Anda.
2. Tambahkan [Project Description] yang singkat.
3. Sesuaikan preferensi Language: sesuai kebutuhan Anda.

    git clone https://github.com/GulajavaMinistudio/awesome-copilot-id.git
  2. Pilih konfigurasi platform Anda:

  4. Mulai ulang IDE atau Asisten AI Anda untuk menerapkan perubahan.

Supplementary (Bypass)

/sdlc-explore-ideas

sdlc-explore-ideas

Mengeksplorasi basis kode secara sistematis, memberikan kritik arsitektur, memetakan struktur repositori ke dalam ARCHITECTURE.md menggunakan skill Project Researcher, dan menghasilkan draft penemuan proyek awal (Phase 0 Discovery).

Paling Cocok Untuk:

Memahami proyek baru atau lama, menganalisis utang teknis, dan menghasilkan peta arsitektur sebelum merumuskan PRD.

Contoh Prompt Penggunaan:
/sdlc-explore-ideas explore the codebase and write a discovery draft for the new shopping cart

/sdlc-draft-prd

sdlc-draft-prd

Menghasilkan Product Requirements Document (PRD) yang komprehensif, mencakup User Stories, alur pengguna, dan kriteria penerimaan.

Paling Cocok Untuk:

Menulis dokumentasi kebutuhan bisnis dan fungsionalitas fitur baru sebelum spesifikasi teknis ditulis.

Contoh Prompt Penggunaan:
/sdlc-draft-prd create a PRD for the user authentication module based on @discovery-draft.md

/sdlc-clarify-reqs

sdlc-clarify-reqs

Melakukan interogasi terhadap PRD, Spesifikasi Teknis, atau Rencana Implementasi untuk menemukan ambiguitas, asumsi tersembunyi, dan edge-case yang terlewat.

Paling Cocok Untuk:

Pengecekan kualitas kebutuhan sebelum melangkah ke spesifikasi teknis atau penulisan kode.

Contoh Prompt Penggunaan:
/sdlc-clarify-reqs interrogate the new @prd-shopping-cart.md for missing edge cases

/sdlc-define-specs

sdlc-define-specs

Membuat spesifikasi teknis detail (kontrak API, skema DB, model data) dan mendokumentasikan keputusan arsitektur penting (ADR).

Paling Cocok Untuk:

Merancang cetak biru teknis sistem yang terstruktur sebelum mulai menulis kode.

Contoh Prompt Penggunaan:

Opsi 1 (Standar):

/sdlc-define-specs design a technical specification based on @prd-shopping-cart.md

Opsi 2 (PRD Bypass):

/sdlc-define-specs design a technical specification based on @discovery-draft.md. Do heavy lifting to guess missing technical details and mark them as [ASSUMPTION].

Opsi 3 (Instruksi Langsung):

/sdlc-define-specs design a technical specification for a real-time chat feature using React and Node.js. Do heavy lifting for any missing details.

/sdlc-audit-consistency

sdlc-audit-consistency

Mengaudit konsistensi dan ketertelusuran dokumen (PRD vs Spec vs Plan) untuk mendeteksi hilangnya cakupan kebutuhan dan scope creep.

Paling Cocok Untuk:

Memastikan alur SDLC konsisten dan tidak ada fitur yang terlupa atau melenceng dari rencana awal.

Contoh Prompt Penggunaan:
/sdlc-audit-consistency verify that @spec-shopping-cart.md covers all requirements in @prd-shopping-cart.md

/sdlc-clarify-reqs

sdlc-clarify-reqs

Melakukan interogasi terhadap PRD, Spesifikasi Teknis, atau Rencana Implementasi untuk menemukan ambiguitas, asumsi tersembunyi, dan edge-case yang terlewat.

Paling Cocok Untuk:

Pengecekan kualitas kebutuhan sebelum melangkah ke spesifikasi teknis atau penulisan kode.

Contoh Prompt Penggunaan:
/sdlc-clarify-reqs interrogate the new @spec-shopping-cart.md for any technical ambiguities

/sdlc-plan-tasks

sdlc-plan-tasks

Memecah Spesifikasi Teknis menjadi langkah-langkah implementasi strategis yang terstruktur dan dapat dieksekusi secara berurutan.

Paling Cocok Untuk:

Menyusun jadwal tugas coding yang terperinci dan aman sebelum developer mulai menulis kode.

Contoh Prompt Penggunaan:

Opsi 1 (Standar):

/sdlc-plan-tasks create a step-by-step implementation plan based on @spec-shopping-cart.md

Opsi 2 (Assumption Scanning):

/sdlc-plan-tasks create an implementation plan based on @spec-shopping-cart.md. Extract any [ASSUMPTION] tags into the Risks & Assumptions section and label related tasks as [High Risk].

/sdlc-clarify-reqs

Paling Cocok Untuk:

Pengecekan kualitas kebutuhan sebelum melangkah ke spesifikasi teknis atau penulisan kode.

/sdlc-write-code

sdlc-write-code

Agen developer otonom tingkat tinggi untuk menulis kode, melakukan modifikasi bedah, dan menulis pengujian unit/integrasi secara ketat.

Paling Cocok Untuk:

Menulis kode fitur, memodifikasi file, memperbaiki error, dan menguji fungsionalitas secara langsung di workspace.

Contoh Prompt Penggunaan:
/sdlc-write-code implement the shopping cart based on @plan-shopping-cart.md

/sdlc-code-review

sdlc-code-review

Meninjau kualitas kode berdasarkan prinsip SOLID, Clean Code, dan aspek keamanan, serta memberikan rencana refaktorisasi.

Paling Cocok Untuk:

Menjaga standar kebersihan kode dan melakukan audit keamanan sebelum digabungkan (merge) ke branch utama.

Contoh Prompt Penggunaan:
/sdlc-code-review review my service layer and suggest refactoring

/sdlc-bug-report

sdlc-bug-report

Menganalisis laporan bug, melacak akar penyebab masalah (RCA), dan menyusun rencana perbaikan bedah beserta strategi rollback yang aman.

Paling Cocok Untuk:

Menyelesaikan masalah bug yang kompleks di codebase tanpa merusak bagian kode lainnya.

Contoh Prompt Penggunaan:
/sdlc-bug-report analyze the bug report in @issue-123.md and propose a fix for @cart.js

/sdlc-generate-docs

sdlc-generate-docs

Penulis dokumentasi teknis profesional yang mengikuti kerangka kerja Diátaxis (Tutorial, Panduan, Referensi, Penjelasan).

Paling Cocok Untuk:

Menulis panduan pengguna, dokumentasi API, dan penjelasan sistem yang mudah dipahami.

Contoh Prompt Penggunaan:
/sdlc-generate-docs write an API reference guide based on @spec-shopping-cart.md

/code-janitor

code-janitor

Agen minimalis super cepat yang menggabungkan perencanaan mikro dan eksekusi dalam satu alur kerja untuk perbaikan ad-hoc dan refaktor kecil di luar proses SDLC yang ketat.

Paling Cocok Untuk:

Perbaikan bug cepat, pembersihan kode, dan refactoring minor yang tidak membutuhkan dokumen PRD-Spec-Plan lengkap.

Contoh Prompt Penggunaan:
/code-janitor tolong refaktor fungsi calculateTotal di @cart.js agar lebih ringkas

/guided-learning

guided-learning

AI-Guided Learning mentor. Memandu pengguna selangkah demi selangkah untuk membangun proyek atau mengimplementasikan rencana tanpa menulis kode secara langsung.

Paling Cocok Untuk:

Digabungkan bersama /sdlc-write-code atau /code-janitor sebagai alternatif "Mentor Mode" agar pengguna dapat belajar mengetik kodenya sendiri.

Contoh Prompt Penggunaan:
/sdlc-write-code implement @plan.md using guided-learning

💡 Alur Kerja & Contoh

Pahami bagaimana siklus hidup pengembangan perangkat lunak (SDLC) dijalankan menggunakan rangkaian agen AI secara sekuensial.

Sekuens Alur SDLC Agen AI

Phase 0: Project Discovery (Penemuan Proyek)

Eksplorasi kode yang ada, analisis arsitektur, dan buat draf penemuan proyek awal sebelum merancang PRD.

Agent: /sdlc-explore-ideas Dokumen Input: Business Brief / Ideas 
/sdlc-explore-ideas explore the codebase and write a discovery draft for the new shopping cart feature based on @business-brief.md

Phase 1: Requirements & Clarification (Kebutuhan & Klarifikasi)

Buat PRD yang terperinci dan lakukan klarifikasi/interogasi mendalam untuk menghilangkan ambiguitas kebutuhan fitur.

Agent: /sdlc-draft-prd & /sdlc-clarify-reqs Dokumen Input: Discovery Draft 
/sdlc-draft-prd create a PRD for the shopping cart feature based on @discovery-draft.md

Phase 2: Technical Specification (Spesifikasi Teknis)

Rancang arsitektur detail, buat skema data, definisikan API, dan catat keputusan arsitektur penting (ADR) serta pastikan ketertelusurannya dengan PRD.

Agent: /sdlc-define-specs, /sdlc-audit-consistency, & /sdlc-clarify-reqs (Opsional) Dokumen Input: Approved PRD 
/sdlc-define-specs design a technical specification based on @prd-shopping-cart.md

Phase 3: Implementation Planning (Rencana Implementasi)

Pecah spesifikasi teknis menjadi langkah-langkah implementasi strategis dan buat checklist rencana coding yang aman.

Agent: /sdlc-plan-tasks & /sdlc-clarify-reqs (Opsional) Dokumen Input: Approved Spec 
/sdlc-plan-tasks create a step-by-step implementation plan based on @spec-shopping-cart.md

Phase 4: Execution & Review (Eksekusi Kode & Tinjauan)

Tulis kode fitur secara bertahap dan teratur berdasarkan rencana yang disetujui, tambahkan pengujian unit, serta lakukan peninjauan kode.

Agent: /sdlc-write-code & /sdlc-code-review Dokumen Input: Approved Plan 
/sdlc-write-code implement the shopping cart based on @plan-shopping-cart.md, and ensure all tests pass

Phase 5: User Documentation & Support (Dokumentasi Pengguna)
